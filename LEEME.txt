FINANZAS — VERSIÓN 1.8
SEGURIDAD Y AISLAMIENTO MULTIUSUARIO

BASE DE PARTIDA
Esta versión parte de Finanzas 1.7.1. Conserva la autenticación Supabase,
la sincronización incremental, las tablas individuales y los respaldos locales.

CAMBIOS DE LA VERSIÓN 1.8
- Endurecimiento de Row Level Security (RLS) para perfiles y tablas financieras.
- Cada usuario autenticado solo puede leer, insertar, modificar y eliminar filas
  cuyo id (profiles) o user_id (tablas financieras) coincide con auth.uid().
- Las políticas RLS anteriores de las tablas indicadas se sustituyen por políticas
  estrictas de propietario para evitar que políticas permisivas antiguas se combinen.
- Se habilita RLS en las tablas protegidas. No se fuerza sobre el propietario
  de tabla para no interferir con el trigger que crea perfiles nuevos.
- Las funciones get_finanzas_data y sync_finanzas_data quedan ejecutables solo
  por el rol authenticated, no por anon ni public.
- Al cambiar de cuenta, la interfaz limpia primero los datos en memoria mientras
  carga el perfil nuevo para evitar mostrar brevemente datos de la sesión anterior.
- Al cerrar sesión, la interfaz vuelve a un estado vacío por defecto y no carga
  automáticamente los datos locales anónimos.
- La importación de datos locales a una cuenta requiere confirmación explícita
  y advierte que no se deben importar datos de otra persona en dispositivos compartidos.
- Si falla la carga de una cuenta, la interfaz no deja visibles los datos de la
  sesión anterior. Las copias locales por usuario no se eliminan.

ANTES DE PUBLICAR
1. En Finanzas, exporta una copia JSON y guárdala en un lugar privado.
2. En Supabase > SQL Editor, abre una consulta nueva.
3. Ejecuta SEGURIDAD_MULTIUSUARIO_V1_8.sql una sola vez.
4. Debe terminar con Success. No rows returned.
5. Ejecuta VERIFICAR_SEGURIDAD_V1_8.sql y revisa que las 12 tablas muestren
   rls_habilitado = true, rls_forzado = true y cuatro politicas finanzas_owner_*.
6. Si el SQL falla, NO publiques todavía la versión. La transacción revierte
   todos sus cambios. Comparte el error para ajustar el script a tu esquema real.

PUBLICAR
1. Descomprime el ZIP.
2. Sube el contenido de la carpeta finanzas a la raíz del repositorio APPFinanzas.
3. Reemplaza los archivos anteriores y haz Commit changes.
4. Espera GitHub Pages y recarga con Ctrl + Shift + R.

PRUEBAS MULTIUSUARIO
- Usuario A inicia sesión y crea un movimiento de prueba.
- Usuario B inicia sesión en otro perfil/navegador o dispositivo y confirma que
  no ve movimientos, cuentas, deudas ni suscripciones del usuario A.
- Usuario B crea un movimiento y confirma que aparece solo en su propia cuenta.
- Usuario A vuelve a iniciar sesión y confirma que sus datos siguen intactos.
- Cerrar sesión debe dejar la interfaz sin los datos privados de la cuenta anterior.

IMPORTANTE
- Esta versión no modifica ni elimina filas financieras.
- No borra profiles.app_data, snapshots ni lotes históricos.
- El script reemplaza las políticas RLS existentes de las 12 tablas indicadas.
  Si hay políticas personalizadas adicionales, deben revisarse antes de ejecutar.
- Las pruebas desde SQL Editor con rol postgres no simulan auth.uid() de un usuario.
  La validación de aislamiento debe hacerse iniciando sesión con dos cuentas reales.
- No compartas contraseñas, service_role ni claves secretas.
